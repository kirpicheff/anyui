# Правила разработки и консистентности AnyUI

Документ задаёт обязательные инварианты и чек-листы для разработчиков и AI-агентов при работе с репозиторием `github.com/kirpicheff/anyui`.

## Обязательные чек-пойнты перед коммитом

После **любого** изменения экспортированного API (сигнатур, типов, опций, констант, поведения):

```bash
go run ./cmd/genllms          # перегенерация llms.txt и llms-full.txt (никогда не править руками)
go run ./cmd/genllms -check   # контроль актуальности и встроенный lintOutputs
go vet ./...                  # статический анализ всех пакетов
go test -count=1 ./...        # все модульные, headless, DPI и doc-sync тесты
go build ./...                # сборка всех пакетов и cmd/demo
```

Если `go run ./cmd/genllms -check` падает — правьте исходники или `cmd/genllms/main.go` (карту API, матрицу опций, правила), а не сгенерированные `llms*.txt`.

## Инварианты

1. **Источник истины — код, `llms.txt` и `llms-full.txt` — производные.** Редактировать `llms*.txt` вручную запрещено; изменения вносятся только через `cmd/genllms/main.go` и перегенерацию.
2. **Прикладной код и `cmd/demo` импортируют только корневой пакет `github.com/kirpicheff/anyui`.** Подпакеты `ui/`, `render/`, `platform/` являются внутренними и не должны утекать в сигнатуры публичного API или в `cmd/demo`.
3. **Строгая дисциплина единиц измерения (`Dp` vs `Px`):**
   - `Dp` — весь API раскладки, контейнеров, опций, оверлеев и Headless-ввода (`LayoutRect`, `Tooltip`, `PushOverlay`, `Popover`, `ContextMenu`, `RegisterHoverArea`, `CurrentArea`, `MousePosDp`, `InjectMouse*`).
   - `Px` — только колбэки рисования (`CanvasView`, `InteractiveCanvas`, `Table*`, `ListView*`), `Canvas`, `DrawText`/`DrawSVG`, `CurrentAreaPx`, `MousePosPx`, `LastDirtyRectsPx`, `TitleBarHitTest`, `InjectMouse*Px` и граница ОС (`Config`, `Window`).
   - Каждое новое исключение или метод с `Rect` должно быть явно задокументировано в правилах `Dp`/`Px`.
4. **Зеркальность `docs/en/*` и `docs/ru/*`:** оба каталога содержат одинаковый набор файлов и разделов; изменение документации на одном языке требует синхронного обновления парного файла.
5. **Рабочие планы не коммитятся:** файлы планов (`*_PLAN.md`, `ROADMAP.md`) исключены через `.gitignore`.
6. **Кроссплатформенный CI:** все проверки должны проходить на Windows, Linux (`CGO_ENABLED=0`) и macOS (`CGO_ENABLED=0` и `CGO_ENABLED=1`).
7. **Стиль сообщений коммитов git:** на русском языке, без слова «Фаза», в прошедшем времени / форме свершившегося факта («Обновлена версия…», «Добавлен…», «Исправлена…», «Повышена…»), а **не** в инфинитиве или повелительном наклонении (запрещено писать «Обновить…», «Добавить…», «Исправить…» как призыв к действию).

## Чек-лист: добавление нового виджета

1. **Реализация в `ui/`:**
   - Метод `func (c *Context) Name(...)` в тематическом `ui/controls_*.go`.
   - Если виджет принимает `id string` — обязательно вызвать `id = c.ResolveID("prefix", id)` в начале метода (для `IDScope` и пустого `id == ""`).
   - Если поддерживается `Disabled()` — блокировать **весь** ввод (фокус, `RegisterHit`, ховер, клики, колесо, клавиатуру, `Reorder`).
   - При использовании `allocRectStyled` — явно читать `st.WidthDp > 0` и `st.HeightDp > 0` до выделения прямоугольника (`applySizeConstraints` обрабатывает только `<= 0` / `Auto`, `Fill*`, `Min*`, `Max*`).
   - Если docstring дублируется с корневым пакетом (как `DragEvent` и `Reorder*`) — обе копии должны быть идентичны (проверяется `TestDocstringSync*` в `ui/doc_sync_test.go`).
2. **Экспорт в корневой пакет `anyui`:**
   - Фасадный метод `func (u *UI) Name(...)` в `ui.go` / `ui_controls.go` / `ui_controls_extra.go` / `ui_desktop.go`.
   - В сигнатурах используются только типы корневого пакета (`Dp`, `Px`, `Rect`, `Color`, `Option` и т. д.), без `ui.*` / `render.*` / `platform.*`.
   - Новые опции `Option` добавляются парой: в `ui/options.go` и тонкой обёрткой в корневом `options.go`.
3. **Обновление `cmd/genllms/main.go`:**
   - Добавить виджет в карту API (`writeShortLLMs`, соответствующая категория).
   - Добавить виджет в `optionMatrixRows` — указывать **только реально работающие** в коде опции.
   - Если дефолтный размер нестандартный — указать его (в `dp`) в правиле «Единое задание размеров через опции».
   - Если возвращаемое значение не `void` (`bool`, `string`, структура события) — отразить в разделе «Семантика возвращаемых значений».
   - Если метод принимает `Rect` — указать, трактуется он как `Dp` или `Px`, в правилах `Dp`/`Px`.
4. **Демо, тесты и документация:**
   - Добавить виджет в соответствующую вкладку `cmd/demo/`.
   - Добавить тест в `ui/*_test.go` (рендер, базовое взаимодействие, `IDScope`/`Disabled`/опции) и при необходимости DPI-проверку в `dpi_layout_test.go` / `ui_coords_test.go`.
   - Для крупного виджета или подсистемы — синхронно обновить `docs/en/*.md` и `docs/ru/*.md`.

## Чек-лист: добавление метода `App` / `Window` / `Headless` / `Canvas`

- После `go run ./cmd/genllms` убедиться, что метод попал в `llms-full.txt`.
- Добавить метод в соответствующую категорию карты API в `cmd/genllms/main.go` (`writeShortLLMs`; для `Canvas` и `SingleInstanceGuard` список строится автоматически).
- Если метод вводит или меняет контракт жизненного цикла/многопоточности/единиц — обновить раздел «Правила работы с API» в `cmd/genllms/main.go`.

## Чек-лист: изменение поведения существующего API

1. Найти все упоминания изменённого символа в `cmd/genllms/main.go`, `docs/en/*`, `docs/ru/*` и `options.go`.
2. Обновить формулировки так, чтобы они точно описывали новое поведение (без смешивания старого и нового).
3. Обновить или добавить тест, фиксирующий новое поведение.
4. Выполнить все обязательные чек-пойнты (`genllms`, `-check`, `vet`, `test`, `build`).
